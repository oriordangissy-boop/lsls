# 对标研究与网站框架

## 建议的产品定位

本项目应定位为：

> 商品编码登记 + 价格透明公示

而不是“二维码防伪”“品牌官方背书”或“真伪鉴定”。

二维码可确认某个编码在销售方系统中是否有一条公开记录；它不能单独证明顾客手上的实物为真，因为二维码可被复制。只有品牌授权主体、实物检验、保卡/表背/包装的共同核对，以及必要时防拆标签或安全 NFC，才能提高信任等级。

## 对标案例

| 对标 | 可借鉴之处 | 不应照搬的结论 |
| --- | --- | --- |
| [Patek Philippe 收藏与参考号检索](https://www.patek.com/en/collection/watch-finder?filter=215) | 用系列、参考号、材质等基础事实组织内容；版面克制、图像与档案资料优先于促销词。 | 不能仿冒其商标、网页布局或将自己的数据称作品牌档案。 |
| [Patek Philippe 档案摘录规则](https://www.patek.com/en/service/frequently-asked-questions/extract-from-the-archives) | 原厂档案只依据参考号、机芯号、表壳号和实物照片等证据；“证书”与“摘录”有明确边界。 | 销售方二维码不可替代制造商档案或原厂证书。 |
| [Rolex Certified Pre-Owned 认证流程](https://www.rolex.com/en-us/buying-a-rolex/rolex-certified-pre-owned/certification-process) | 认证的强度与证据链匹配：原厂工作坊检验、密封、保卡和保修共同构成认证。 | 没有同等的实体检验与授权时，不可使用“官方认证”措辞。 |
| [Breitling Digital Passport](https://www.breitling.com/li-en/about/digital-passport/) | 保卡二维码作为入口；产品资料、保修、历史与所有权能力分层呈现。 | 公开扫码页不应直接暴露完整所有权或私人维修资料。 |
| [IWC My IWC Passport](https://www.iwc.com/us-en/services/faq) | 单表使用参考号、序列号和限量号；QR 是入口而非全部证据。 | 不能把普通连续编码直接当成数字证书。 |
| [Chrono24 估值方法说明](https://www.chrono24.com/info/valuation.htm/index.htm) | 市场价受参考号、品相、盒证、材质、年份、复杂功能等因素影响；使用数据范围和平均价。 | 挂牌价、成交价、建议零售价不可混在一起。 |

## 目标客户旅程

~~~text
扫描标签
  ↓
公开单表登记页（不要求登录）
  ↓
看见：登记状态 / 图片 / 款号 / 唯一编码 / 销售方公示价
  ↓
展开：海外可比价格依据、来源、日期、币种、口径
  ↓
核对：表背、保卡或包装上的实体编码
  ↓
不一致或状态异常 → 人工核验
~~~

## 页面信息架构

首屏只回答客户的三个问题：

1. 这只表是否在销售方系统中登记？
2. 公开售价是什么、何时生效？
3. 实体上的编码是否与页面一致？

随后依次呈现：

1. 商品身份：商品图、款号、颜色/配置、可见唯一编码、限量号。
2. 价格记录：销售方公示价、价格生效日、价格版本、税费边界。
3. 价格依据：海外公开参考资料、原币、挂牌/成交类型、抓取日期、相似性说明。
4. 记录历史：签发、改价、作废、补发等不可覆盖的事件。
5. 边界说明：网页能证明什么、不能证明什么；人工核验入口。

## 价格口径

| 数据类型 | 用语 | 必需证据 |
| --- | --- | --- |
| 品牌官方建议零售价 | 品牌建议零售价 | 品牌方或授权经销商可核实的定价文件 |
| 销售方价格 | 销售方公示价 / 建议零售价 | 价格责任主体、生效日、价格版本 |
| 精确同款的海外样本 | 海外公开同款价格参考 | 同一参考号、配置、品相、盒证、来源链接、抓取日期 |
| 相近款的海外样本 | 海外公开可比款价格参考 | 说明差异，不能写成同款或估值 |

海外样本至少保留：

- 来源 URL 和网页快照/存档编号
- 商品标题、参考号、币种、原始金额
- 挂牌或已成交的类型
- 品相、附件、年份、材质和机芯（可得时）
- 抓取日期、汇率日期、税费/运费是否计入
- 纳入或排除的原因

## 编号设计

建议将三个概念拆开：

~~~text
款号：ZY-3038LB.01
本型号限量号：001 / 050
系列总量：1,000 枚
二维码令牌：不可预测的随机值
~~~

二维码只携带随机令牌，实际页面再显示款号和限量号。二维码不应携带连续序列号、价格或后台接口。

## 实施路径

### 第一阶段：静态 Git 原型

- 本项目当前完成的范围。
- 验证视觉、客户阅读流程、价格证据结构和标签尺寸。
- 数据保存在 Git 中，适合演示和小规模人工维护。

### 第二阶段：独立站后台

- 数据库保存单表、价格版本、来源样本和审计日志。
- 随机令牌服务端查询；支持待启用、有效、已售、补发、作废。
- 后台加入多因素认证、角色权限、导入校验、备份与速率限制。
- 对外公开页不要求手机号或微信授权。

### 第三阶段：提高物理信任

- 表背、保卡、包装与站内记录同码。
- 防拆封签/镭射等物理措施。
- 高价值款可增加带动态验签的安全 NFC；QR 保持兼容入口。

## 视觉方向

不是复刻任何瑞士品牌，而是建立“时计档案”的独立识别：

- 深墨蓝：像机芯、蓝钢和档案盒，承担信任和底色。
- 象牙纸白：像证书纸张，承担信息阅读。
- 铂金灰：承担数据、边界和辅助信息。
- 暖金：只用于价格记录与证据索引。
- 中文衬线字体用于价格与标题，等宽字体用于唯一编码和数据日期。
- 页面签名元素是“证据时间轴”：每条价格与记录都可以被追溯到一个日期，而不是靠夸张徽章制造信任。
